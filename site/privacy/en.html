HoopLab is a private iPhone app built by one athlete for personal use. It can have two users: its owner and one person the owner invites. New sign-ups are closed and the app is not publicly released. This page explains what the app does with data, including data it reads from Google with the owner's permission and from Apple Health with the invited user's permission. The source code is public, so every statement here can be checked in the repository.

Data the app reads from Google (owner)

With the owner's consent, the app's server reads data from the Google Health API using four read-only permissions: activity and fitness, health metrics and measurements, sleep, and settings. In practice this means daily summaries such as heart rate variability, resting and sleeping heart rate, blood oxygen, breathing rate, skin temperature, steps, distance, calories and active minutes, plus sleep and exercise sessions. The app never writes to Google and does not download the raw all-day heart rate stream.

Data the app reads from Apple Health (invited user)

On the invited user's iPhone, the app reads from Apple Health (HealthKit) with the permission the user grants in iOS: heart rate variability, resting heart rate and heart rate samples, sleep stages, breathing rate, active and basal energy, steps, walking and running distance, and workouts. If the user turns on Cycle Tracking, menstrual flow records and cycle deviations are read as well. Daily values are calculated on the phone; the server receives only daily and nightly summaries, sleep and workout sessions and hourly energy, not raw samples. Menstrual records never leave the phone: only the cycle day and an estimated phase are sent. The app never writes to Apple Health. HealthKit data is not used for advertising, not written to iCloud and never sold.

How the data is used

The data is used only to show each user their own numbers inside the app, compared with their own baseline, with every threshold linked to a scientific source. An optional AI coach explains the numbers the app has already calculated. The app is not a medical device and does not diagnose.

Where it is stored and who receives it

  • Supabase (database and server functions, Frankfurt, EU) stores the data. Row-level security lets each account read only its own rows: the two users cannot see each other's data.
  • The app's owner administers the database and can therefore technically see the invited user's data. The invited user reads and accepts this on an explicit consent screen at first sign-in; without consent, no data is read or sent.
  • Anthropic (Claude API) receives the numbers the app has calculated (for example "heart rate variability below your usual range") when a user asks the AI coach for a summary or answer. It does not receive name, email, date of birth or raw time series. Anthropic does not use API data to train its models by default.
  • Expo (notification delivery) passes the title and text of a reminder to the iPhone if the user turns reminders on; these texts contain no health values.
  • Nothing is sold, used for advertising or shared with anyone else. A user may export a weekly PDF and send it to someone of their choosing, such as a physiotherapist.

Google API Services User Data Policy

HoopLab's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Google user data is used only to provide the features described above, is not used to develop, improve or train general AI or machine learning models, and is not read by humans except for security purposes, to comply with law, or with the owner's explicit consent.

Keeping and deleting data

Data is kept until the user asks for it to be deleted. The invited user asks the owner to delete their account and all of their data; deleting the account deletes all of its rows. Apple Health access can be turned off at any time on the iPhone under Settings, Health, Data Access. Disconnecting Google in the app (Me, then Google Health, then Disconnect) revokes the permission at Google and deletes the stored token; access can also be removed from the Google Account's security settings. Requests sent to the Anthropic API are deleted by Anthropic, by default within 30 days.
